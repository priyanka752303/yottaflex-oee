# AI usage disclosure

**Tool:** Claude Code (Anthropic), model Claude Opus 5.5. The full prompt history is in [`prompts/PROMPT_HISTORY.md`](prompts/PROMPT_HISTORY.md).

## Where AI did the heavy lifting

I relied heavily on AI for almost all of the first draft.

* **Requirements.** It read the brief and the two PDFs, and turned them into a checklist of requirements (entities, edge cases, the 10 generation steps and the acceptance criteria).
* **Design.**
  * The data model, including the bridge table for versioned ideal cycle times, the break and order-history tables, and the append-only corrections and annotations.
  * The OEE rule set (planned downtime, micro-stop threshold, overlap precedence, counter quarantine) and the decision to separate ground truth from the calculator.
* **Code and tests.** All code in `oee/` and `tests/`, generated in a few iterations.
* **Documentation.** The README, `docs/DESIGN.md`, this file and `SOURCE_MANIFEST.md`. The data dictionary, ERD and DDL are generated by code.

## Where AI accelerated, and how its output was checked

The AI's output is checked by machine, not just by reading it.

* **Calculator vs simulation.** The calculator is scored against the generator's own simulation, which is a separate code path. At full scale:
  * All 125 injected anomalies are detected, with 0 false positives.
  * 8,053 of 8,100 machine-shifts match the expected OEE exactly.
  * The other 47 are the rows where the true value is unknowable (overlapping states, impossible scrap). They are flagged `EXCEPTION`.
* **Validation.** 150 validation checks cover types, enums, ID formats, primary keys, foreign keys, time order, lifecycles, duplicates and arithmetic reconciliation. SQLite also enforces the foreign keys on load (`PRAGMA foreign_key_check`).
* **Tests.** 20 unit and end-to-end tests. They include a naive recomputation of availability straight from raw events, and a byte-level reproducibility test.
* **Reproducibility.** `python -m oee repro` regenerates twice and compares checksums.
